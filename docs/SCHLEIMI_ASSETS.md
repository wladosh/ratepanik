# Schleimi asset bible (2.0 — parametric SVG)

Style lead for the **Schleimi** mascot. Original character only. No copyrighted characters, no real-person likeness, no gore.

Since Schleimi 2.0 the avatar is **not** built from layered PNGs anymore. Every part is inline SVG defined in code, and facial features are positioned parametrically via per-shape anchors, so **every combination fits by construction**.

## Character

**Schleimi** is a cute, brainy slime blob: round, glossy, a little too proud of knowing the answer. Vibe is a German living-room party quiz — *peinlich-lustig*, not corporate mascot, not horror goo. Personality lives in shape, face, and backdrop — Schleimi has no human body, hats, or held props.

## Where the art lives

| File | Role |
| --- | --- |
| `src/lib/schleimi-parts.tsx` | The entire part library: shapes, palettes, eyes, mouths, backgrounds |
| `src/components/schleimi-preview.tsx` | Compositor: background → body (shape ∘ palette) → eyes → mouth |
| `src/lib/schleimi-catalog.ts` | Item metadata: ids, slots, rarities, names, sort order |
| `src/app/dev/schleimi/page.tsx` | Dev-only QA grid rendering every part and combination |

There is no PNG export pipeline for avatar parts. Only **crate art** (`public/rp/schleimi/lootbox_*.png`, generated by `scripts/gen_slot_crates.py`) remains raster.

## Coordinate system and anchors

All parts share one **0..100 viewBox**.

- **Shapes** are filled silhouette paths sitting on y ≈ 88, spanning roughly x 14..86 (star/ghost may reach 10..90). Each shape declares:
  - `eyeY` — y of the eye-line center
  - `mouthY` — y of the mouth center
  - `faceScale` — scale for face parts (< 1 on narrow shapes)
  - optional `shadowPath` (inner contact shadow, filled with `palette.shade`) and `highlightPath` (top gloss, `palette.highlight` at 0.55 opacity)
- **Eyes and mouths** are drawn centered at (0,0); the renderer translates them to `(50, eyeY)` / `(50, mouthY)` and scales by `faceScale`. Eyes stay within x −18..18, y −8..8; mouths within x −12..12, y −6..8. They receive the palette's `ink` color.
- **Palettes** are pure parameters: `base`, `shade`, `highlight`, `ink`, optional vertical `gradient` (gold/holo).
- **Backgrounds** render a full 0..100 square, clipped to a rounded rect by the compositor. Every `<defs>` id **must** be prefixed with the passed `uid` so multiple avatars can coexist on one page.

## Style rules

- Thick, readable shapes; one idea per part. Everything must read at **40–48px** header size and **88px** shop tiles (UI canvas is 390×844).
- Soft pastel blob volume: one highlight, one inner contact shadow. Not photoreal, not thin lineart. Face strokes ≥ ~2 units in the 100-viewBox (≈ 2% of avatar width).
- No detail that vanishes at 48px: no micro-patterns, 1px sparkles, or text.

## Adding a new part

1. Add the SVG definition to the matching record in `src/lib/schleimi-parts.tsx`, following the coordinate rules above.
2. Add the catalog entry (id, slot, rarity, names, sort) in `src/lib/schleimi-catalog.ts`.
3. Insert the matching `cosmetic_items` row via a migration (`asset_path` is the logical key `svg:<id>`).
4. Verify it on `/dev/schleimi` at all sizes and on every shape (for face parts).

## Legacy (pre-2.0)

The PNG layer system (`slot_<slot>__<rarity>__<slug>.png`, `schleimi_base.png`, hat/extra slots) was removed in the Schleimi 2.0 migration (`supabase/migrations/20260829_021_schleimi_v2_svg.sql`). Legacy `face` items were decomposed into eyes + mouth pairs; `hat`/`extra` items were refunded as Hirncoins.
